# 시작할 때 새 테이블 만들기

웹 서비스가 시작될 때 새 기능에 필요한 **테이블만** 만드는 단계다. 데이터베이스에 직접 접근하지 못해도 릴리스 배포만으로 새 기능의 테이블이 생기게 하려는 것이다. 구현은 `schema/AdditiveSchemaMigrator.kt`, SQL은 `src/main/resources/db/additive/`.

## 규칙

- **새 테이블과 새 인덱스를 `IF NOT EXISTS`로 만드는 문장만 허용한다.** 기존 테이블이나 행을 바꾸거나 지우는 마이그레이션(`ALTER`, `UPDATE`, `DELETE`, `DROP`, `INSERT`, `DO $$ ... $$`)은 여기에 넣지 않는다. 코드가 파일 내용을 검사해서 그런 문장이 하나라도 있으면 아무것도 실행하지 않는다(`REFUSED`). 그런 마이그레이션은 DB 권한이 있는 사람이 직접 적용한다.
- **허용 목록은 코드의 `FILES`다.** `db/additive/`에 파일을 넣고 `FILES`에 이름을 추가하지 않으면 실행되지 않는다. 폴더의 파일이 목록에서 빠져 있으면 테스트가 실패한다.
- 파일이 만드는 테이블 중 하나라도 없을 때만 그 파일을 실행한다. 이미 다 있으면 아무것도 하지 않는다.
- 실행할 파일들은 **하나의 트랜잭션**으로 묶인다(중간에 실패하면 전부 되돌아간다). 잠금 대기는 5초로 제한하고, DB 전체에서 한 번에 한 인스턴스만 실행한다(advisory lock).
- **서비스 시작을 막지 않는다.** DB 계정에 `CREATE` 권한이 없거나, 잠금 대기가 넘치거나, 어떤 오류가 나도 로그만 남기고 서비스는 정상 시작한다.
- 설정 `kkutu.schema.auto-apply=false`로 끌 수 있다(기본은 켜짐).

## 결과 확인

관리자 API `GET /api/admin/schema/check`(권한 `API_ACCESS`)의 `autoMigration`에 이번 시작에서 한 일이 나온다.

| `state` | 뜻 |
|---|---|
| `APPLIED` | `applied`에 적힌 파일을 실행했다 |
| `UP_TO_DATE` | 만들 것이 없었다 |
| `DENIED` | DB 계정에 테이블을 만들 권한이 없다. 아무것도 만들지 않았다 |
| `LOCK_TIMEOUT` | 잠금을 5초 안에 얻지 못했다. 다음 시작 때 다시 시도한다 |
| `SKIPPED_LOCKED` | 다른 인스턴스가 적용 중이다 |
| `REFUSED` | 허용 범위를 벗어난 SQL이 들어 있어 실행하지 않았다 |
| `ERROR` | 그 밖의 오류. `message`에 원인 |
| `DISABLED` | 설정으로 꺼져 있다 |

같은 응답의 `summary`와 `problems`는 각 마이그레이션이 DB에 들어 있는지(`APPLIED`/`MISSING`/`PARTIAL`)를 카탈로그에서 읽어 보여 준다.

## 주의

- 테이블이 생긴 뒤 이전 릴리스로 되돌려도 테이블은 남는다. 새 테이블뿐이라 해가 없다.
- 이 단계가 만드는 것은 모양뿐이다. 새 테이블에 넣을 기본 데이터가 필요하면 그 기능의 코드나 별도 절차가 한다.
